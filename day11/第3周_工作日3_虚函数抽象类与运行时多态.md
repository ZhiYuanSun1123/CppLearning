## 4. 为什么需要虚函数

先看没有虚函数的代码：

```cpp
#include <iostream>

class Model {
public:
    void infer() const {
        std::cout << "Model::infer\n";
    }
};

class AudioModel : public Model {
public:
    void infer() const {
        std::cout << "AudioModel::infer\n";
    }
};

void run_model(const Model& model) {
    model.infer();
}

int main() {
    AudioModel audio_model;
    run_model(audio_model);
}
```

输出：

```text
Model::infer
```

虽然传入的真实对象是`AudioModel`，但`run_model()`中的参数类型是：

```cpp
const Model& model
```

而`Model::infer()`不是虚函数，所以编译器根据表达式的静态类型`Model`决定调用基类版本。

这叫静态绑定，也可称为早绑定。

```text
编译阶段看到类型Model
        ↓
决定调用Model::infer()
```

## 5. 使用`virtual`启用动态绑定

把基类函数声明为虚函数：

```cpp
class Model {
public:
    virtual void infer() const {
        std::cout << "Model::infer\n";
    }
};
```

派生类重写：

```cpp
class AudioModel : public Model {
public:
    void infer() const override {
        std::cout << "AudioModel::infer\n";
    }
};
```

完整调用：

```cpp
void run_model(const Model& model) {
    model.infer();
}

int main() {
    AudioModel audio_model;
    run_model(audio_model);
}
```

输出变成：

```text
AudioModel::infer
```

这次调用由对象的运行时真实类型决定：

```text
参数静态类型：Model&
对象真实类型：AudioModel
          ↓
运行时选择AudioModel::infer()
```

这叫动态绑定或运行时多态。

## 6. `virtual`和`override`分别写在哪里

基类：

```cpp
class Model {
public:
    virtual void infer() const;
};
```

派生类：

```cpp
class AudioModel : public Model {
public:
    void infer() const override;
};
```

基本规则：

- 基类用`virtual`声明这是一个多态接口；
- 派生类用`override`明确表示“我要重写基类虚函数”；
- 派生类可以同时写`virtual`和`override`，但通常只写`override`更清楚；
- 基类函数一旦成为虚函数，它在后续派生类中仍然保持虚函数性质。

推荐风格：

```cpp
class Base {
public:
    virtual void run() const;
};

class Derived : public Base {
public:
    void run() const override;
};
```

---

## 7. 为什么必须使用`override`

如果不写`override`：

```cpp
class Model {
public:
    virtual void infer() const;
};

class AudioModel : public Model {
public:
    void infer();  // 少了const
};
```

这不是重写，而是声明了一个新的函数。

原因是下面两个函数签名不同：

```cpp
void infer();
void infer() const;
```

加上`override`：

```cpp
class AudioModel : public Model {
public:
    void infer() override;
};
```

编译器会直接报错，提醒你它没有正确重写基类接口。

因此：

> `override`不是为了实现多态，而是让编译器替你检查重写是否正确。

常见的不匹配包括：

- 少写或多写`const`；
- 参数类型不同；
- 参数数量不同；
- 函数名拼错；
- 引用限定不同；
- 基类函数根本不是虚函数。

## 8. 基类引用和基类指针

运行时多态通常通过基类引用或基类指针发生。

### 基类引用

```cpp
void run_model(const Model& model) {
    model.infer();
}
```

调用：

```cpp
AudioModel audio_model;
run_model(audio_model);
```

特点：

- 不能是空引用；
- 不负责对象所有权；
- 语法接近普通对象；
- 适合“必须传入一个有效模型”的场景。

### 基类指针

```cpp
void run_model(const Model* model) {
    if (model == nullptr) {
        return;
    }

    model->infer();
}
```

调用：

```cpp
AudioModel audio_model;
run_model(&audio_model);
```

特点：

- 可以是`nullptr`；
- 使用前需要检查；
- 同样可以触发运行时多态；
- 指针本身不一定拥有对象。

今天优先使用基类引用，因为练习中的模型必须存在，不需要表达“没有模型”。

## 9. 什么是纯虚函数

如果基类无法给出合理的通用实现，可以只规定接口：

```cpp
class Model {
public:
    virtual void infer(
        const std::string& input
    ) const = 0;
};
```

末尾的：

```cpp
= 0
```

表示纯虚函数。

注意：

- `= 0`不是把函数赋值为数字0；
- 它表示该函数是一个必须由派生类实现的接口；
- 只要类中仍有未实现的纯虚函数，该类就是抽象类。

---

## 10. 什么是抽象类

包含纯虚函数的类通常是抽象类：

```cpp
class Model {
public:
    virtual void infer(
        const std::string& input
    ) const = 0;
};
```

不能直接创建抽象类对象：

```cpp
Model model;  // 编译错误
```

因为`Model`只规定“模型必须能够推理”，却没有说明具体怎么推理。

可以创建完成接口实现的派生类对象：

```cpp
class AudioModel : public Model {
public:
    void infer(
        const std::string& input
    ) const override {
        std::cout
            << "Audio inference: "
            << input
            << '\n';
    }
};
```

```cpp
AudioModel model;
```

抽象类可以：

- 拥有构造函数；
- 拥有析构函数；
- 拥有数据成员；
- 拥有普通成员函数；
- 拥有已经实现的虚函数；
- 作为引用或指针类型使用。

抽象类只是不能直接实例化。

## 11. 抽象类仍然可以有状态

下面的`Model`保存公共模型名称，同时把推理过程留给派生类：

```cpp
#include <stdexcept>
#include <string>

class Model {
public:
    explicit Model(const std::string& name)
        : name_(name) {
        if (name_.empty()) {
            throw std::runtime_error(
                "模型名称不能为空"
            );
        }
    }

    const std::string& name() const {
        return name_;
    }

    virtual void infer(
        const std::string& input
    ) const = 0;

    virtual ~Model() = default;

private:
    std::string name_;
};
```

这里出现两个今天只需理解的写法：

```cpp
explicit Model(...)
```

`explicit`用于阻止单参数构造函数发生意外隐式转换，后续会专门复习。

```cpp
virtual ~Model() = default;
```

表示这是一个虚析构函数，并让编译器生成默认实现。

## 12. 为什么多态基类通常需要虚析构函数

观察：

```cpp
class Model {
public:
    virtual void infer() const = 0;
    ~Model() = default;
};

class AudioModel : public Model {
public:
    ~AudioModel() {
        std::cout << "Destroy AudioModel\n";
    }

    void infer() const override {
    }
};
```

如果通过基类指针删除派生类对象：

```cpp
Model* model = new AudioModel;
delete model;
```

基类析构函数不是虚函数时，这种删除具有未定义行为，派生类析构函数可能不会被正确调用。

正确写法：

```cpp
class Model {
public:
    virtual void infer() const = 0;
    virtual ~Model() = default;
};
```

现在：

```cpp
Model* model = new AudioModel;
delete model;
```

能够沿着正确的析构链释放对象。

今天需要记住：

> 只要类准备被当作多态基类使用，通常就应该声明虚析构函数。

这不代表所有类的析构函数都必须是虚函数。普通值类型和不用于多态的类通常不需要虚析构函数。

---

## 13. `= default`是什么

```cpp
virtual ~Model() = default;
```

意思是：

> 这个析构函数由编译器按照默认规则生成，但它仍然是虚函数。

它大致表达：

```cpp
virtual ~Model() {
}
```

`= default`的优势是更明确地告诉读者：这里需要这个特殊成员函数，但不需要自定义清理逻辑。

这属于特殊成员函数控制语法，后续还会与：

```cpp
= delete
```

一起系统复习。

## 14. 什么是对象切片

假设：

```cpp
class Model {
public:
    virtual void infer() const {
        std::cout << "Model\n";
    }
};

class AudioModel : public Model {
public:
    void infer() const override {
        std::cout << "AudioModel\n";
    }
};
```

错误示范：

```cpp
void run_model(Model model) {
    model.infer();
}
```

调用：

```cpp
AudioModel audio_model;
run_model(audio_model);
```

按值把`AudioModel`传给`Model`参数时，只复制基类部分，派生类特有部分被切掉。

这叫对象切片。

```text
AudioModel完整对象
├── Model基类部分
└── AudioModel派生部分

按值转换成Model
└── 只剩Model基类部分
```

避免方法：

```cpp
void run_model(const Model& model);
```

或者：

```cpp
void run_model(const Model* model);
```

因此，多态接口不要使用基类按值参数。

## 15. `const`必须匹配

基类：

```cpp
virtual void infer(
    const std::string& input
) const = 0;
```

派生类必须同样保留末尾的`const`：

```cpp
void infer(
    const std::string& input
) const override;
```

下面是错误的：

```cpp
void infer(
    const std::string& input
) override;
```

末尾少了`const`，函数签名不一致。因为写了`override`，编译器会指出问题。

参数本身的`const`和成员函数末尾的`const`含义不同：

```cpp
const std::string& input
```

表示不能通过`input`修改传入字符串。

```cpp
void infer(...) const
```

表示这个函数不能修改当前对象的普通数据成员。

## 16. 构造函数为什么不能是虚函数

虚函数调用依赖对象已经具有确定的运行时类型。

但构造函数的工作正是创建对象、建立对象类型和状态，因此构造函数不能声明为虚函数：

```cpp
class Model {
public:
    virtual Model();  // 错误
};
```

析构函数可以是虚函数，因为销毁时对象已经存在，并且通过基类指针删除时需要知道真实派生类型。

简单记忆：

```text
构造函数：不能virtual
析构函数：多态基类通常应该virtual
```

---

## 17. 静态成员函数不能是虚函数

虚函数针对某个具体对象进行动态派发。

静态成员函数不属于某个具体对象，也没有`this`指针，因此不能声明为虚函数：

```cpp
class Model {
public:
    static virtual void version(); // 错误
};
```

数据成员也不能是虚的：

```cpp
virtual int sample_rate_; // 错误
```

只有符合条件的非静态成员函数可以成为虚函数。

## 18. 一个完整的运行时多态示例

文件：`src/example_runtime_polymorphism.cpp`

```cpp
#include <iostream>
#include <stdexcept>
#include <string>

class Model {
public:
    explicit Model(const std::string& name)
        : name_(name) {
        if (name_.empty()) {
            throw std::runtime_error(
                "模型名称不能为空"
            );
        }
    }

    const std::string& name() const {
        return name_;
    }

    virtual void infer(
        const std::string& input
    ) const = 0;

    virtual ~Model() = default;

private:
    std::string name_;
};

class AudioModel : public Model {
public:
    AudioModel(
        const std::string& name,
        int sample_rate
    )
        : Model(name),
          sample_rate_(sample_rate) {
        if (sample_rate_ <= 0) {
            throw std::runtime_error(
                "采样率必须大于0"
            );
        }
    }

    void infer(
        const std::string& input
    ) const override {
        std::cout
            << name()
            << " processes audio \""
            << input
            << "\" at "
            << sample_rate_
            << " Hz\n";
    }

private:
    int sample_rate_;
};

class TextModel : public Model {
public:
    explicit TextModel(
        const std::string& name
    )
        : Model(name) {
    }

    void infer(
        const std::string& input
    ) const override {
        std::cout
            << name()
            << " processes text \""
            << input
            << "\"\n";
    }
};

void run_model(
    const Model& model,
    const std::string& input
) {
    std::cout
        << "Selected model: "
        << model.name()
        << '\n';

    model.infer(input);
}

int main() {
    AudioModel audio_model(
        "Qwen-Omni",
        16000
    );

    TextModel text_model(
        "Qwen-Text"
    );

    run_model(
        audio_model,
        "input.wav"
    );

    run_model(
        text_model,
        "hello"
    );

    return 0;
}
```

预期输出：

```text
Selected model: Qwen-Omni
Qwen-Omni processes audio "input.wav" at 16000 Hz
Selected model: Qwen-Text
Qwen-Text processes text "hello"
```

同一个函数：

```cpp
run_model(const Model& model, ...)
```

既可以处理`AudioModel`，也可以处理`TextModel`。新增另一种模型时，`run_model()`通常不需要修改。

这就是统一接口带来的价值。

## 19. 运行时多态成立的四个基础条件

在今天的基础场景中，可以用四点判断：

1. 存在合理的公开继承关系；
2. 基类声明虚函数；
3. 派生类正确重写虚函数；
4. 通过基类引用或基类指针调用。

例如：

```cpp
class Model {
public:
    virtual void infer() const = 0;
    virtual ~Model() = default;
};
```

```cpp
class AudioModel : public Model {
public:
    void infer() const override {
    }
};
```

```cpp
void run(const Model& model) {
    model.infer();
}
```

如果改为按值传递：

```cpp
void run(Model model);
```

不仅可能发生对象切片，而且抽象类`Model`本身也不能作为按值参数被正常构造。

## 20. 运行时多态的成本

运行时多态不是完全没有成本，通常包括：

- 对象可能需要保存用于动态派发的信息；
- 虚函数调用通常比直接普通函数调用多一次间接寻址；
- 某些情况下会限制编译器内联优化；
- 接口设计错误会增加继承层次复杂度。

但今天不要过度担心性能。

对于推理系统而言，模型推理本身通常远比一次虚函数调用昂贵。先使用清晰、正确的接口，再通过Benchmark决定是否优化。

不能仅凭“虚函数可能有开销”就提前删除合理的多态设计。

---

## 21. 什么时候适合运行时多态

适合：

- 多个类共享稳定的统一接口；
- 调用者不应该依赖具体实现；
- 运行时才知道使用哪种实现；
- 未来可能增加新的实现；
- 真实关系符合`is-a`。

例如：

```text
WhisperModel is a Model
QwenOmniModel is a Model
MockModel is a Model
```

不适合：

- 只是为了复用两行代码；
- 类之间没有真实`is-a`关系；
- 不需要运行时切换实现；
- 一个简单组合就能解决；
- 接口并不稳定。

## 22. 常见错误

### 错误1：基类忘记写`virtual`

```cpp
class Model {
public:
    void infer() const;
};
```

基类引用调用时会选择基类版本。

### 错误2：派生类不写`override`

代码可能暂时能运行，但签名写错时编译器无法按照你的意图检查。

### 错误3：`const`不匹配

```cpp
virtual void infer() const;
void infer() override;
```

不是同一个函数签名。

### 错误4：直接创建抽象类对象

```cpp
Model model;
```

抽象类不能实例化。

### 错误5：按值传递基类

```cpp
void run(Model model);
```

可能造成对象切片。

### 错误6：多态基类没有虚析构函数

通过基类指针删除派生对象可能产生未定义行为。

### 错误7：把所有函数都写成虚函数

只有需要由派生类提供不同实现并进行动态派发的接口才需要成为虚函数。

### 错误8：在构造函数或析构函数中期待完整派生类动态派发

对象构造和析构期间的动态派发规则与普通阶段不同。今天先避免在构造函数、析构函数中调用可重写虚函数，后续再深入。

## 30. 练习8：把昨天的服务升级为运行时多态

|概念|核心含义|今天的例子|
|---|---|---|
|普通成员函数|根据静态类型确定调用|非虚`Model::infer()`|

```text
服务和具体模型绑定
```

```text
服务依赖统一Model接口
       ├── WhisperModel
       └── QwenOmniModel
```
