# 第一部分：给Demo添加命令行参数

## 3. 接入CLI11

在 `day27/CMakeLists.txt` 现有的FetchContent区域增加：

```cmake
FetchContent_Declare(
    CLI11
    GIT_REPOSITORY https://github.com/CLIUtils/CLI11.git
    GIT_TAG v2.5.0
    GIT_SHALLOW TRUE
)

FetchContent_MakeAvailable(CLI11)
```

找到demo的链接配置，增加 `CLI11::CLI11`：

```cmake
target_link_libraries(
    tensor_metadata_demo
    PRIVATE
    tensor_metadata
    project_warnings
    fmt::fmt
    CLI11::CLI11
)
```

理解：

```text
CLI11::CLI11是CMake target
PRIVATE表示只有demo使用它
核心tensor_metadata库不依赖CLI11
```

## 4. 修改 `day27/app/main.cpp`

### 4.1 增加头文件

```cpp

```

### 4.2 修改main声明

```cpp
int main(int argc, char* argv[]) {
```

```text
argc：参数数量
argv：参数字符串数组
```

### 4.3 在main开头准备参数

```cpp
CLI::App app{"Inspect tensor metadata"};

std::string name = "mel_features";
std::size_t batch = 1;
std::size_t time = 3000;
std::size_t feature = 80;
int device_index = 0;
```

### 4.4 注册选项

```cpp
app.add_option(
    "--name",
    name,
    "Tensor name"
);

app.add_option(
    "--batch",
    batch,
    "Batch dimension"
)->check(CLI::PositiveNumber);

app.add_option(
    "--time",
    time,
    "Time dimension"
)->check(CLI::PositiveNumber);

app.add_option(
    "--feature",
    feature,
    "Feature dimension"
)->check(CLI::PositiveNumber);

app.add_option(
    "--device-index",
    device_index,
    "Device index"
)->check(CLI::NonNegativeNumber);
```

`add_option()`返回选项对象，所以可以继续调用 `->check()` 添加校验。这属于CLI11的接口用法，今天不分析其模板实现。

### 4.5 解析参数

```cpp
CLI11_PARSE(app, argc, argv);
```

CLI11会处理：

```text
--help
未知选项
缺少参数值
类型转换失败
范围校验失败
错误退出码
```

### 4.6 使用参数创建对象

```cpp
const TensorMetadata metadata(
    name,
    TensorShape({batch, time, feature}),
    DataType::float32,
    TensorLayout::batch_time_feature,
    Device(DeviceType::accelerator, device_index)
);
```

# 第二部分：安装库、头文件和Demo

## 5. 加载安装模块

在 `day27/CMakeLists.txt` 的 `project()` 后加入：

```cmake
include(GNUInstallDirs)
include(CMakePackageConfigHelpers)
```

今天只需要记住：

```text
CMAKE_INSTALL_BINDIR       通常是bin
CMAKE_INSTALL_LIBDIR       通常是lib
CMAKE_INSTALL_INCLUDEDIR   通常是include
```

---

## 6. 修正公开头文件路径

把现有代码：

```cmake
target_include_directories(
    tensor_metadata
    PUBLIC
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)
```

修改为：

```cmake
target_include_directories(
    tensor_metadata
    PUBLIC
    "$<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>"
    "$<INSTALL_INTERFACE:${CMAKE_INSTALL_INCLUDEDIR}>"
)
```

```text
BUILD_INTERFACE
    在day27源码中构建时使用

INSTALL_INTERFACE
    安装后被其他项目使用时生效
```

这是今天最重要的知识点之一。

---

## 7. 避免内部警告target泄漏

把：

```cmake
target_link_libraries(
    tensor_metadata
    PRIVATE
    project_warnings
)
```

修改为：

```cmake
target_link_libraries(
    tensor_metadata
    PRIVATE
    "$<BUILD_INTERFACE:project_warnings>"
)
```

原因：

```text
project_warnings只服务当前项目开发
安装后的消费者不需要继承它
```

否则导出时可能提示 `project_warnings` 不在导出集合中。

---

## 8. 添加安装规则

在 `day27/CMakeLists.txt` 末尾加入：

```cmake
install(
    TARGETS tensor_metadata
    EXPORT TensorMetadataTargets
    ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR}
    LIBRARY DESTINATION ${CMAKE_INSTALL_LIBDIR}
    RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR}
    INCLUDES DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
)

install(
    TARGETS tensor_metadata_demo
    RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR}
)

install(
    DIRECTORY include/
    DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
    FILES_MATCHING
    PATTERN "*.hpp"
)
```

对应关系：

```text
tensor_metadata      → lib
tensor_metadata_demo → bin
include/*.hpp        → include
```

测试程序只服务开发和CI，不安装。

## 10. 生成Config和Version文件

在 `day27/CMakeLists.txt` 末尾继续加入：

```cmake
set(
    TensorMetadata_INSTALL_CMAKEDIR
    ${CMAKE_INSTALL_LIBDIR}/cmake/TensorMetadata
)

configure_package_config_file(
    cmake/TensorMetadataConfig.cmake.in
    ${CMAKE_CURRENT_BINARY_DIR}/TensorMetadataConfig.cmake
    INSTALL_DESTINATION
        ${TensorMetadata_INSTALL_CMAKEDIR}
)

write_basic_package_version_file(
    ${CMAKE_CURRENT_BINARY_DIR}/TensorMetadataConfigVersion.cmake
    VERSION ${PROJECT_VERSION}
    COMPATIBILITY SameMajorVersion
)
```

三个文件的分工：

```text
Config
    find_package入口

Version
    检查版本

Targets
    定义TensorMetadata::tensor_metadata
```

## 11. 安装三个CMake包文件

```cmake
install(
    EXPORT TensorMetadataTargets
    FILE TensorMetadataTargets.cmake
    NAMESPACE TensorMetadata::
    DESTINATION
        ${TensorMetadata_INSTALL_CMAKEDIR}
)

install(
    FILES
        ${CMAKE_CURRENT_BINARY_DIR}/TensorMetadataConfig.cmake
        ${CMAKE_CURRENT_BINARY_DIR}/TensorMetadataConfigVersion.cmake
    DESTINATION
        ${TensorMetadata_INSTALL_CMAKEDIR}
)
```

`NAMESPACE TensorMetadata::` 让消费者使用：


## 16. consumer的 `CMakeLists.txt`

新建：

```text
day32/consumer/CMakeLists.txt
```

内容：

```cmake
cmake_minimum_required(VERSION 3.20)

project(
    TensorMetadataConsumer
    LANGUAGES CXX
)

find_package(
    TensorMetadata 1.0
    CONFIG
    REQUIRED
)

add_executable(
    tensor_metadata_consumer
    main.cpp
)

target_compile_features(
    tensor_metadata_consumer
    PRIVATE
    cxx_std_17
)

target_link_libraries(
    tensor_metadata_consumer
    PRIVATE
    TensorMetadata::tensor_metadata
)
```

这里不需要自己设置include路径和库文件路径。

## 17. consumer的 `main.cpp`

新建：

```text
day32/consumer/main.cpp
```

内容：

```cpp
#include "tensor_metadata.hpp"

#include <iostream>

int main() {
    const TensorMetadata metadata(
        "consumer_tensor",
        TensorShape({1, 200, 80}),
        DataType::float32,
```

# 错误定位

## 21. 常见错误表

| 现象 | 常见原因 |
|---|---|
| 找不到 `CLI/CLI.hpp` | demo没有链接 `CLI11::CLI11` |
| CLI11下载失败 | 网络、代理或Git访问问题 |
| 导出时报 `project_warnings` 缺失 | 内部target泄漏到安装接口 |
| consumer找不到包 | Config没安装或PrefixPath错误 |
| consumer找不到头文件 | INSTALL_INTERFACE或头文件安装错误 |
| consumer链接失败 | 库或Targets导出错误 |
| 安装后的demo不能运行 | 运行时动态库路径问题 |
| 非法参数仍进入业务逻辑 | CLI11解析位置不正确 |

先判断错误阶段：

```text
CMake配置
编译
链接
安装
find_package
运行
```
