```bash

```

保存报告：

```bash
./example_asan 2>&1 | tee asan-report.txt
```

查看退出码：

```bash
echo $?
```

### VS Code 参数注意事项

在 `tasks.json` 中必须写成三个独立参数：

```json
"-Wall",
"-Wextra",
"-Wpedantic",
```

不能写成：

```json
"-Wall -Wextra -Wpedantic"
```

否则 Clang 会把它当成一个不存在的警告选项。

### macOS 的分配释放不匹配检查

如果测试：

```cpp

```

配合：

```cpp

```

但 ASan 没有输出，可以显式启用：

```bash

```

保存报告：

```bash
ASAN_OPTIONS=alloc_dealloc_mismatch=1 \
./example_asan 2>&1 | tee asan-report.txt
```

## 3. 错误定位的统一流程

每个故意包含错误的程序都按以下流程完成：

```text
1. 先阅读代码
2. 不运行，先预测错误
3. 使用ASan编译
4. 运行并触发错误
5. 记录错误类型
6. 找到自己代码中的报错行
7. 找到分配位置
8. 找到第一次释放位置
9. 解释根本原因
10. 修改代码
11. 重新编译
12. 重新运行并确认无ASan报告
```

注意：

- 不要只看报告最后一行；
- 不要只把指针设为 `nullptr` 而不修复生命周期；
- 不要通过删除程序功能来让错误消失；
- 每修复一次都必须重新编译；
- 旧可执行文件不能代表新源码已编译成功。

## 12. 练习 8：RAII 异常路径复习

这道题只复习 RAII 思想，不考查类的高级语法。

文件：`08_raii_exception_review.cpp`

```cpp
#include <cstdio>
#include <iostream>
#include <stdexcept>
#include <string>

class FileHandle {
public:
    FileHandle(
        const std::string& path,
        const char* mode
    ) {
        file_ = std::fopen(
            path.c_str(),
            mode
        );

        if (file_ == nullptr) {
            throw std::runtime_error(
                "文件打开失败"
            );
        }

        std::cout << "文件打开\n";
    }

    ~FileHandle() {
        if (file_ != nullptr) {
            std::fclose(file_);
            std::cout << "文件关闭\n";
        }
    }

    void write(const std::string& text) {
        std::fputs(text.c_str(), file_);
    }

private:
    std::FILE* file_ = nullptr;
};

void process() {
    FileHandle file("raii_result.txt", "w");
    file.write("data before exception\n");

    std::cout << "抛出异常\n";
    throw std::runtime_error("模拟失败");
}

int main() {
    try {
        process();
    } catch (const std::exception& error) {
        std::cerr << "捕获异常: "
                  << error.what()
                  << '\n';
    }

    return 0;
}
```

2. 编译并运行；

5. 删除 `throw` 再测试正常路径；

## 15. 一个合格错误说明的示例

### 堆数组写越界

错误代码：

```cpp
const int size = 5;
int* values = new int[size]{};

for (int index = 0;
     index <= size;
     ++index) {
    values[index] = index;
}
```

错误类型：

```text
heap-buffer-overflow
```

非法操作：

```text
WRITE of size 4
```

根本原因：

```text
数组长度为5时合法下标为0～4。
循环条件index <= size允许index等于5，
因此程序向动态数组合法区域之后写入一个int。
```

修复：

```cpp
for (int index = 0;
     index < size;
     ++index) {
    values[index] = index;
}
```

防止再次发生：

- 循环遍历数组统一使用 `index < size`；
- 不把元素数量当作最后一个合法下标；
- 调试版本启用 ASan；
- 对边界为 0、1 和正常长度的输入进行测试。

注意：合格的说明必须包含“为什么”，不能只写：

```text
把<=改成<。
```

## 16. ASan 报告阅读清单

每次看到报告，依次寻找：

### 1. 错误类型

```text
heap-buffer-overflow
stack-buffer-overflow
heap-use-after-free
attempting double-free
alloc-dealloc-mismatch
```

### 2. 非法操作

```text
READ of size 4
WRITE of size 4
```

### 3. 自己代码中的第一处位置

例如：

```text
main example.cpp:20
```

### 4. 分配位置

```text
allocated by thread T0 here
```

### 5. 释放位置

```text
freed by thread T0 here
```

### 6. 区域边界

例如：

```text
0 bytes after 20-byte region
```

### 7. Summary

例如：

```text
SUMMARY: AddressSanitizer: heap-buffer-overflow
```

`Summary` 是错误报告的摘要，不是完整根因分析。

## 18. RAII 复习：能保证和不能保证

RAII 能帮助保证：

- 对象正常离开作用域时执行清理；
- 提前 `return` 时执行局部对象析构；
- 异常栈展开时执行已构造对象的析构；
- 清理代码集中在资源类中；
- 减少遗漏释放的风险。

RAII 不能保证：

- 资源申请一定成功；
- 文件写入一定成功；
- 业务结果一定正确；
- 文件内容具有事务完整性；
- 错误的所有权设计自动正确；
- 强制杀死进程或断电时一定完成清理；
- 多线程访问自动安全。

今天需要能够用一句话概括：

> RAII 管理的是资源生命周期，不是业务逻辑的全部正确性。
