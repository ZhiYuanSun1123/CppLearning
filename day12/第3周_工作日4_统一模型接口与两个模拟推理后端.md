## 4. 为什么需要统一模型接口

没有统一接口时，调用者可能分别依赖具体类型：

```cpp
class WhisperBackend {
public:
    void transcribe(
        const std::string& audio_path
    ) const;
};

class QwenOmniBackend {
public:
    void reason_about_audio(
        const std::string& audio_path,
        const std::string& question
    ) const;
};
```

调用代码可能变成：

```cpp
void run_whisper(
    const WhisperBackend& backend
);

void run_qwen(
    const QwenOmniBackend& backend
);
```

或者出现手动判断：

```cpp
if (backend_name == "whisper") {
    // 调用Whisper
} else if (backend_name == "qwen") {
    // 调用Qwen
}
```

这种设计的问题：

- 每增加一个模型就要增加一套调用代码；
- 服务必须知道所有具体模型类型；
- 参数和返回格式不统一；
- 测试代码难以复用；
- 后续真实部署时难以替换推理实现。

今天要把调用关系改为：

```text
InferenceService
        ↓
只依赖ModelBackend接口
        ↓
运行时可接收不同实现
        ├── WhisperBackend
        └── QwenOmniBackend
```

---

## 5. 什么是统一接口

统一接口不是要求所有后端内部实现相同，而是要求调用者使用相同的调用方式。

例如：

```cpp
class ModelBackend {
public:
    virtual std::string infer(
        const std::string& input
    ) const = 0;

    virtual ~ModelBackend() = default;
};
```

两个实现：

```cpp
class WhisperBackend
    : public ModelBackend {
public:
    std::string infer(
        const std::string& input
    ) const override;
};
```

```cpp
class QwenOmniBackend
    : public ModelBackend {
public:
    std::string infer(
        const std::string& input
    ) const override;
};
```

调用者只需要：

```cpp
void run(
    const ModelBackend& backend,
    const std::string& input
) {
    std::cout << backend.infer(input);
}
```

调用者不需要判断具体类型，虚函数负责运行时选择实现。

## 6. 接口应该放什么

一个基础模型后端接口可以描述：

- 后端名称；
- 后端是否可用；
- 推理操作；
- 虚析构函数。

```cpp
class ModelBackend {
public:
    explicit ModelBackend(
        const std::string& name
    );

    const std::string& name() const;

    virtual bool is_ready() const = 0;

    virtual std::string infer(
        const std::string& input
    ) const = 0;

    virtual ~ModelBackend() = default;

private:
    std::string name_;
};
```

其中：

```cpp
name()
```

所有后端逻辑相同，因此由基类提供普通成员函数。

```cpp
is_ready()
infer()
```

不同后端可能行为不同，因此声明为纯虚函数。

---

## 7. 接口不应该放什么

不要把某个具体后端特有的实现细节塞进统一接口：

```cpp
class ModelBackend {
public:
    virtual void load_whisper_tokenizer() = 0;
    virtual void build_tensorrt_engine() = 0;
    virtual void set_qwen_audio_prompt() = 0;
};
```

这些接口并非所有后端都适用。

基础统一接口应表达调用者真正共同需要的能力：

```cpp
virtual bool is_ready() const = 0;
virtual InferenceResult infer(
    const InferenceRequest& request
) const = 0;
```

具体加载、预处理和运行细节由派生类内部实现。

## 8. 请求对象

直接向`infer()`传递多个零散参数：

```cpp
infer(
    audio_path,
    question,
    max_tokens,
    language
);
```

参数继续增加时接口会越来越长。

今天使用一个简单请求类：

```cpp
class InferenceRequest {
public:
    InferenceRequest(
        const std::string& audio_path,
        const std::string& question
    )
        : audio_path_(audio_path),
          question_(question) {
        if (audio_path_.empty()) {
            throw std::runtime_error(
                "音频路径不能为空"
            );
        }

        if (question_.empty()) {
            throw std::runtime_error(
                "问题不能为空"
            );
        }
    }

    const std::string& audio_path() const {
        return audio_path_;
    }

    const std::string& question() const {
        return question_;
    }

private:
    std::string audio_path_;
    std::string question_;
};
```

这是普通的值对象，不涉及真实文件读取。

## 10. 最终抽象接口

```cpp
class ModelBackend {
public:
    explicit ModelBackend(
        const std::string& name
    )
        : name_(name) {
        if (name_.empty()) {
            throw std::runtime_error(
                "后端名称不能为空"
            );
        }
    }

    const std::string& name() const {
        return name_;
    }

    virtual bool is_ready() const = 0;

    virtual InferenceResult infer(
        const InferenceRequest& request
    ) const = 0;

    virtual ~ModelBackend() = default;

private:
    std::string name_;
};
```

设计说明：

- `ModelBackend`是抽象类；
- `name_`由基类统一维护；
- `name()`不需要虚函数；
- `is_ready()`由各后端决定；
- `infer()`由各后端实现；
- 虚析构函数保证多态销毁安全；
- 数据成员保持`private`。

## 13. 静态数据成员是什么

普通数据成员属于每个对象：

```cpp
class Model {
private:
    int id_;
};
```

如果创建两个对象：

```cpp
Model first;
Model second;
```

则存在两份`id_`。

静态数据成员属于整个类：

```cpp
class Model {
private:
    inline static int count_ = 0;
};
```

无论创建多少对象，`count_`只有一份：

```text
first对象 ──┐
second对象 ─┼──> Model::count_
third对象 ──┘
```

因此，模拟后端用静态变量统计该类型总共执行了多少次推理比较合理。

## 14. C++17的`inline static`

传统写法：

```cpp
class Model {
public:
    static int count_;
};
```

类外还需要定义：

```cpp
int Model::count_ = 0;
```

你当前使用C++17，可以写：

```cpp
class Model {
public:
    inline static int count_ = 0;
};
```

这样可以直接在类定义中完成初始化。

今天优先使用：

```cpp
inline static
```

## 15. 静态成员函数

静态成员函数同样属于类，而不是具体对象：

```cpp
class WhisperBackend {
public:
    static int inference_count() {
        return inference_count_;
    }

private:
    inline static int inference_count_ = 0;
};
```

推荐通过类名调用：

```cpp
std::cout
    << WhisperBackend::inference_count()
    << '\n';
```

语法上也可以通过对象调用：

```cpp
WhisperBackend backend("Whisper");
backend.inference_count();
```

但不推荐，因为它容易让读者误以为函数依赖`backend`对象。

---

## 16. 静态成员函数没有`this`

普通成员函数概念上会接收当前对象：

```cpp
void print() const;
```

函数内部可以访问：

```cpp
this->name_
```

静态成员函数没有`this`：

```cpp
static int inference_count();
```

因此不能直接访问普通对象成员：

```cpp
class Model {
public:
    static void print_name() {
        // std::cout << name_; // 错误
    }

private:
    std::string name_;
};
```

它可以直接访问类的静态成员：

```cpp
static int count() {
    return count_;
}
```

---

## 17. 静态成员函数不能有末尾`const`

错误：

```cpp
static int count() const;
```

末尾`const`约束的是：

```text
this指向的当前对象
```

静态函数没有`this`，所以不能使用末尾`const`。

正确：

```cpp
static int count();
```

但是参数和返回值仍然可以有`const`：

```cpp
static void print(
    const std::string& text
);
```

## 18. 为什么`const infer()`可以增加静态计数

```cpp
InferenceResult infer(
    const InferenceRequest& request
) const override {
    ++inference_count_;
}
```

末尾的`const`表示：

```text
不能修改当前后端对象的普通成员状态
```

但：

```cpp
inference_count_
```

属于整个类，不属于当前对象，所以可以修改。

```text
const WhisperBackend对象
├── 对象自己的非static成员不能修改
└── WhisperBackend::inference_count_可以修改
```

如果静态数据自身声明为`const`：

```cpp
inline static const int max_count_ = 100;
```

则不能修改它，因为变量本身是常量。

---

## 19. 静态成员函数不能是虚函数

错误：

```cpp
class ModelBackend {
public:
    static virtual void reset();
};
```

原因：

- 虚函数根据具体对象的动态类型选择；
- 静态成员函数不属于具体对象；
- 静态成员函数没有`this`；
- 因此不存在基于对象的动态派发。

虚函数通过对象调用：

```cpp
backend.infer(request);
```

静态函数通过类调用：

```cpp
WhisperBackend::inference_count();
```

## 20. 同名函数的名称隐藏

```cpp
class ModelBackend {
public:
    void print_info() const {
        std::cout
            << "ModelBackend info\n";
    }
};

class WhisperBackend
    : public ModelBackend {
public:
    void print_info() const {
        std::cout
            << "WhisperBackend info\n";
    }
};
```

调用：

```cpp
WhisperBackend backend;

backend.print_info();
```

执行子类版本。

明确调用父类版本：

```cpp
backend.ModelBackend::print_info();
```

在子类成员函数内部可以写：

```cpp
ModelBackend::print_info();
```

限定名称明确选择基类实现。

## 21. 同名数据成员

```cpp
class Base {
public:
    int value = 1;
};

class Derived : public Base {
public:
    int value = 2;
};
```

调用：

```cpp
Derived object;

std::cout << object.value << '\n';
std::cout << object.Base::value << '\n';
```

输出：

```text
2
1
```

虽然语法允许，但实际设计中不建议父类和子类保存同名数据成员。

父类成员如果是`private`：

```cpp
class ModelBackend {
private:
    std::string name_;
};
```

子类不能直接访问：

```cpp
// ModelBackend::name_ // 错误
```

应使用父类提供的公开接口：

```cpp
name()
```

## 22. `using Base::function`恢复父类重载

```cpp
class Base {
public:
    void load(int id) {
    }

    void load(
        const std::string& path
    ) {
    }
};

class Derived : public Base {
public:
    void load(double version) {
    }
};
```

子类的`load`会隐藏父类所有同名重载。

恢复父类重载：

```cpp
class Derived : public Base {
public:
    using Base::load;

    void load(double version) {
    }
};
```

现在可以：

```cpp
Derived object;

object.load(1);
object.load("model.bin");
object.load(2.5);
```

这个知识点今天理解即可，后续学习函数重载和模板时会再次遇到。

## 23. 推理服务

推理服务只依赖抽象接口：

```cpp
class InferenceService {
public:
    void run(
        const ModelBackend& backend,
        const InferenceRequest& request
    ) const {
        if (!backend.is_ready()) {
            throw std::runtime_error(
                "后端未就绪: "
                + backend.name()
            );
        }

        std::cout
            << "Selected backend: "
            << backend.name()
            << '\n';

        const InferenceResult result =
            backend.infer(request);

        result.print();
    }
};
```

它没有：

```cpp
if (backend.name() == "Whisper")
```

也没有：

```cpp
dynamic_cast
```

因为虚函数会自动选择真实后端实现。

```cpp
#include <iostream>
#include <stdexcept>
#include <string>

class InferenceRequest {
public:
    InferenceRequest(
        const std::string& audio_path,
        const std::string& question
    )
        : audio_path_(audio_path),
          question_(question) {
        if (audio_path_.empty()) {
            throw std::runtime_error(
                "音频路径不能为空"
            );
        }

        if (question_.empty()) {
            throw std::runtime_error(
                "问题不能为空"
            );
        }
    }

    const std::string& audio_path() const {
        return audio_path_;
    }

    const std::string& question() const {
        return question_;
    }

private:
    std::string audio_path_;
    std::string question_;
};

class InferenceResult {
public:
    InferenceResult(
        const std::string& backend_name,
        const std::string& output
    )
        : backend_name_(backend_name),
          output_(output) {
    }

    const std::string& backend_name() const {
        return backend_name_;
    }

    const std::string& output() const {
        return output_;
    }

    void print() const {
        std::cout
            << "[" << backend_name_ << "] "
            << output_
            << '\n';
    }

private:
    std::string backend_name_;
    std::string output_;
};

class ModelBackend {
public:
    explicit ModelBackend(
        const std::string& name
    )
        : name_(name) {
        if (name_.empty()) {
            throw std::runtime_error(
                "后端名称不能为空"
            );
        }
    }

    const std::string& name() const {
        return name_;
    }

    virtual bool is_ready() const = 0;

    virtual InferenceResult infer(
        const InferenceRequest& request
    ) const = 0;

    virtual ~ModelBackend() = default;

private:
    std::string name_;
};

class WhisperBackend
    : public ModelBackend {
public:
    explicit WhisperBackend(
        const std::string& name
    )
        : ModelBackend(name) {
    }

    bool is_ready() const override {
        return true;
    }

    InferenceResult infer(
        const InferenceRequest& request
    ) const override {
        ++inference_count_;

        const std::string output =
            "Transcribe "
            + request.audio_path()
            + " for question: "
            + request.question();

        return InferenceResult(
            name(),
            output
        );
    }

    static int inference_count() {
        return inference_count_;
    }

private:
    inline static int inference_count_ = 0;
};

class QwenOmniBackend
    : public ModelBackend {
public:
    explicit QwenOmniBackend(
        const std::string& name
    )
        : ModelBackend(name) {
    }

    bool is_ready() const override {
        return true;
    }

    InferenceResult infer(
        const InferenceRequest& request
    ) const override {
        ++inference_count_;

        const std::string output =
            "Reason about "
            + request.audio_path()
            + " and answer: "
            + request.question();

        return InferenceResult(
            name(),
            output
        );
    }

    static int inference_count() {
        return inference_count_;
    }

private:
    inline static int inference_count_ = 0;
};

class InferenceService {
public:
    void run(
        const ModelBackend& backend,
        const InferenceRequest& request
    ) const {
        if (!backend.is_ready()) {
            throw std::runtime_error(
                "后端未就绪: "
                + backend.name()
            );
        }

        std::cout
            << "Selected backend: "
            << backend.name()
            << '\n';

        const InferenceResult result =
            backend.infer(request);

        result.print();
    }
};

int main() {
    try {
        const WhisperBackend whisper(
            "Whisper"
        );

        const QwenOmniBackend qwen(
            "Qwen2.5-Omni"
        );

        const InferenceRequest request(
            "meeting.wav",
            "What happened in the audio?"
        );

        const InferenceService service;

        service.run(
            whisper,
            request
        );

        service.run(
            qwen,
            request
        );

        std::cout
            << "Whisper calls: "
            << WhisperBackend::inference_count()
            << '\n';

        std::cout
            << "Qwen calls: "
            << QwenOmniBackend::inference_count()
            << '\n';
    } catch (
        const std::exception& error
    ) {
        std::cerr
            << "Error: "
            << error.what()
            << '\n';

        return 1;
    }

    return 0;
}
```

## 26. 为什么`const`后端仍可记录调用次数

完整示例创建：

```cpp
const WhisperBackend whisper("Whisper");
```

服务参数：

```cpp
const ModelBackend& backend
```

仍然能够执行：

```cpp
++inference_count_;
```

因为：

```text
whisper对象本身保持不变
WhisperBackend类共享计数发生变化
```

静态计数不属于`whisper`对象的普通状态。

这正是：

```cpp
infer(...) const
```

和静态成员可以同时使用的原因。

## 27. 接口设计中的`const`

```cpp
virtual InferenceResult infer(
    const InferenceRequest& request
) const = 0;
```

第一个`const`：

```cpp
const InferenceRequest&
```

表示后端不能通过该参数修改请求对象。

第二个`const`：

```cpp
) const
```

表示推理调用不能修改当前后端对象的普通成员。

两个派生类必须完全匹配：

```cpp
InferenceResult infer(
    const InferenceRequest& request
) const override;
```

少写末尾`const`会导致`override`编译错误。

## 30. 常见错误

### 错误1：基类没有虚析构函数

```cpp
~ModelBackend() = default;
```

应改为：

```cpp
virtual ~ModelBackend() = default;
```

### 错误2：派生类忘记`override`

```cpp
InferenceResult infer(
    const InferenceRequest& request
) const;
```

推荐：

```cpp
InferenceResult infer(
    const InferenceRequest& request
) const override;
```

### 错误3：签名少了末尾`const`

```cpp
InferenceResult infer(
    const InferenceRequest& request
) override;
```

与基类签名不一致。

### 错误4：服务按值接收抽象基类

```cpp
void run(ModelBackend backend);
```

抽象类不能按值实例化，也不适合多态。

应使用：

```cpp
void run(
    const ModelBackend& backend
);
```

### 错误5：静态函数末尾写`const`

```cpp
static int count() const;
```

静态函数没有`this`，不能使用末尾`const`。

### 错误6：静态函数直接访问对象成员

```cpp
static void print_name() {
    std::cout << name_;
}
```

静态函数不知道具体对象。

### 错误7：忘记`inline static`

只在类中声明：

```cpp
static int count_;
```

但没有类外定义，使用时可能链接失败。

C++17可写：

```cpp
inline static int count_ = 0;
```

### 错误8：通过具体类型重载服务

```cpp
void run(const WhisperBackend&);
void run(const QwenOmniBackend&);
```

这没有真正使用统一接口。

### 错误9：使用`dynamic_cast`分支

```cpp
if (dynamic_cast<const WhisperBackend*>(
        &backend
    ) != nullptr) {
}
```

今天不需要。行为差异应由虚函数实现。

### 错误10：模拟项目写成真实模型项目

今天只需输出可验证字符串，不要安装大型框架或下载模型。
