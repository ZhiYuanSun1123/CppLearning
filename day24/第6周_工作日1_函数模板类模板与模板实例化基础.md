## 4. 为什么需要模板

没有模板时，可能重复编写：

```cpp
int larger_int(int left, int right) {
    return left < right ? right : left;
}

double larger_double(
    double left,
    double right
) {
    return left < right ? right : left;
}
```

算法结构相同，只是类型不同。

函数模板可以表达：

```cpp
template <typename T>
T larger_of(const T& left, const T& right) {
    return left < right ? right : left;
}
```

这里不是创建一个能接收“任何东西”的动态函数，而是让编译器根据使用类型生成相应的具体函数。

---

## 4.1 什么是泛型编程

“泛型”可以理解为：

> 编写不依赖某一个具体类型、但对一组满足要求的类型都适用的代码。

例如，求绝对值的处理结构并不只属于 `int`：

```cpp
int absolute_int(int value);
double absolute_double(double value);
float absolute_float(float value);
```

泛型编程把具体类型抽象成模板参数：

```cpp
template <typename T>
T absolute_value(T value) {
    return value < T{} ? -value : value;
}
```

所以二者的关系是：

```text
模板（template）
    是C++实现泛型编程的重要语言机制

泛型编程（generic programming）
    是让算法和数据结构不依赖具体类型的设计思想
```

模板是工具，泛型是使用这种工具进行抽象和复用的思想。

---

## 4.2 泛型不是“什么类型都可以传”

```cpp
template <typename T>
T add(const T& left, const T& right) {
    return left + right;
}
```

这个模板隐含要求：

```text
T支持operator+
相加结果能够构造或转换为T
T满足参数和返回值需要的复制/移动语义
```

例如：

```cpp
add(1, 2);
add(1.5, 2.5);
add(std::string("a"), std::string("b"));
```

自定义类型如果不支持 `operator+`，模板在该类型上实例化时会报错。

因此泛型代码表示：

```text
对所有满足接口要求的类型复用同一套实现
```

而不是绕过类型系统接收任意数据。

---

## 4.3 泛型关注“能力”而不是“身份”

运行时面向对象接口可能关注：

```text
这个对象是不是ModelBackend的派生类？
```

泛型算法更关注：

```text
这个类型能不能完成算法要求的操作？
```

例如 `std::sort()`不要求元素继承某个共同父类，而是要求：

- 迭代器支持随机访问；
- 元素可以移动或交换；
- 比较器能形成有效的严格顺序。

这就是标准库算法可以处理不同容器元素类型的基础。

---

## 4.4 泛型函数和泛型类型

### 泛型函数

函数模板描述一类函数：

```cpp
template <typename T>
T larger_of(const T& left, const T& right);
```

它可能形成：

```text
larger_of<int>
larger_of<double>
larger_of<std::string>
```

前提是具体类型满足比较等操作要求。

### 泛型类型

类模板描述一类类型：

```cpp
template <typename T>
class FeatureBatch;
```

它可以形成：

```text
FeatureBatch<float>
FeatureBatch<double>
FeatureBatch<int>
```

这些是不同的具体类型，但共享同一套模板结构。

---

## 4.5 泛型编程与编译期多态

模板常被称为编译期多态或静态多态：

```cpp
larger_of(1, 2);       // 实例化int版本
larger_of(1.0, 2.0);   // 实例化double版本
```

类型和实现通常在编译阶段确定。

与虚函数多态对比：

```text
模板泛型
├── 编译时确定具体类型
├── 不要求共同基类
├── 容易内联和针对具体类型优化
└── 可能增加编译时间和代码体积

虚函数多态
├── 运行时根据实际对象分派
├── 通过共同基类表达统一接口
├── 适合运行时切换不同实现
└── 通常需要一次间接调用
```

在你的方向中二者可以共同使用：

```text
FeatureBatch<float/double>
    -> 模板处理不同数值类型

ModelBackend及其派生类
    -> 虚函数在运行时切换Qwen/Whisper后端
```

---

## 4.6 泛型与Python动态类型的区别

Python：

```python
def add(left, right):
    return left + right
```

通常执行到 `+`时才判断实际对象是否支持操作。

C++模板：

```cpp
template <typename T>
T add(const T& left, const T& right) {
    return left + right;
}
```

通常在编译期为具体类型实例化并检查表达式。

```text
Python动态类型
    错误可能在运行路径执行时出现

C++模板泛型
    错误通常在具体模板实例化编译时出现
```

C++泛型仍然是强类型的。

---

## 4.7 泛型与 `void*`的区别

C式通用接口可能使用：

```cpp
void process(void* data);
```

它丢失具体类型信息，需要手动转换，类型不匹配可能产生严重错误。

模板保留具体类型：

```cpp
template <typename T>
void process(T& data);
```

编译器仍然知道 `T`是什么，可以检查成员、运算符和函数参数。

因此模板泛型不是“不安全的万能指针”，而是类型安全的代码复用方式。

---

## 4.8 泛型抽象的三个层次

### 层次1：把具体类型参数化

```cpp
template <typename T>
T square(T value);
```

### 层次2：明确类型必须提供的能力

```text
square要求T支持乘法
larger_of要求T支持比较
FeatureBatch要求T适合数值计算
```

今天通过文档和 `static_assert`表达一部分要求。

### 层次3：围绕操作语义设计接口

```cpp
template <typename Iterator, typename Predicate>
Iterator find_first(
    Iterator first,
    Iterator last,
    Predicate predicate
);
```

它不限定必须是 `vector<int>`，而要求：

- `Iterator`能够遍历和解引用；
- `Predicate`能够接收元素并返回真假。

这接近标准库算法的泛型设计。今天只理解思想，不要求自己实现完整算法库。

## 4.9 什么时候不一定需要模板

- 只支持一个明确类型；
- 普通函数重载已经足够；
- 运行时需要动态切换实现；
- 需要稳定的二进制ABI边界；
- 模板复杂度明显大于复用收益；
- 应由虚函数表达运行时后端差异。

可以使用下面的判断：

```text
变化的是编译期类型，处理结构相同
    -> 考虑模板泛型

变化的是运行时对象行为，需要基类统一调用
    -> 考虑虚函数多态
```

## 5. 函数模板基本语法

```cpp
template <typename T>
T larger_of(const T& left, const T& right) {
    return left < right ? right : left;
}
```

拆分：

```text
template <typename T>  -> 声明模板参数T
T                      -> 返回类型
const T& left          -> 普通函数参数
const T& right         -> 普通函数参数
```

`T`是类型的占位名称，只有实例化时才会变成具体类型。

---

## 6. `typename`与 `class`

下面两种写法在声明类型模板参数时基本等价：

```cpp
template <typename T>
```

```cpp
template <class T>
```

这里的 `class`不要求 `T`必须是类，也可以是：

```text
int
double
指针
结构体
标准库类型
```

现代代码常用 `typename`表达“这是一个类型参数”。同一项目保持风格一致即可。

## 7. 模板参数、模板实参与函数参数

```cpp
template <typename T>
T square(T value) {
    return value * value;
}
```

调用：

```cpp
square<int>(5);
```

其中：

```text
T     -> 模板参数
int   -> 模板实参
value -> 函数参数
5     -> 函数实参
```

不要把模板参数和普通函数参数混为一谈。

## 8. 模板实参自动推导

```cpp
const int result = larger_of(3, 7);
```

编译器从两个参数推导：

```text
T = int
```

```cpp
const double result = larger_of(3.5, 7.2);
```

推导：

```text
T = double
```

你没有写 `<int>`或 `<double>`，但编译器根据函数实参完成推导。

---

## 9. 显式指定模板实参

```cpp
const double result = larger_of<double>(3, 7.5);
```

显式指定：

```text
T = double
```

然后普通参数按函数调用规则转换为 `double`。

不要为了“更明确”在所有调用中强行写模板实参。能够自然推导且语义清楚时，自动推导通常更简洁。

---

## 10. 两个实参类型不一致

```cpp
larger_of(3, 7.5);
```

对于：

```cpp
template <typename T>
T larger_of(const T&, const T&);
```

编译器从第一个参数推导 `T=int`，从第二个参数推导 `T=double`，结果冲突，通常无法完成推导。

解决方式之一是显式指定：

```cpp
larger_of<double>(3, 7.5);
```

也可以设计两个类型参数，但返回类型和比较规则会更复杂：

```cpp
template <typename Left, typename Right>
/* 返回类型 */ larger_of(Left left, Right right);
```

混合类型设计今天只做练习，不扩展到复杂类型推导。

## 11. 模板并不保证所有类型都能使用

```cpp
template <typename T>
T larger_of(const T& left, const T& right) {
    return left < right ? right : left;
}
```

这个模板隐含要求 `T`支持：

```cpp
left < right
```

如果类型没有对应的 `<`，实例化时才会报错。

模板不是：

```text
所有类型无条件可用
```

而是：

```text
对满足模板表达式要求的类型可用
```

C++20 Concepts可以更直接表达要求，但今天不使用。

## 12. 值传递和 `const T&`

值传递：

```cpp
template <typename T>
T identity(T value);
```

会构造函数参数副本或移动对象。

只读引用：

```cpp
template <typename T>
const T& choose_first(
    const T& first,
    const T& second
);
```

避免复制，但返回引用时必须考虑生命周期。

危险调用思想：

```cpp
const std::string& result =
    choose_first(std::string("a"),
                 std::string("b"));
```

临时对象在完整表达式结束后销毁，返回引用可能悬空。

初学阶段，比较函数返回小型值更安全：

```cpp
T larger_of(...);
```

模板不会自动解决引用生命周期问题。

## 13. 数组和指针推导提醒

参数按值时，数组通常会退化为指针：

```cpp
template <typename T>
void inspect(T value);
```

调用：

```cpp
int values[4]{};
inspect(values);
```

`T`通常推导为指针相关类型，数组长度信息丢失。

按数组引用可以保留长度：

```cpp
template <typename T, std::size_t N>
std::size_t array_size(const T (&)[N]) {
    return N;
}
```

这里 `N`是非类型模板参数，后面会解释。

## 14. 多个模板参数

```cpp
template <typename Input, typename Output>
Output convert_value(const Input& input) {
    return static_cast<Output>(input);
}
```

调用时 `Output`无法从返回类型推导，因为函数模板推导通常不根据接收返回值的变量反向推导：

```cpp
const double result =
    convert_value<int, double>(42);
```

也可以调整模板参数顺序，让调用更方便：

```cpp
template <typename Output, typename Input>
Output convert_value(const Input& input);
```

调用：

```cpp
convert_value<double>(42);
```

`Output`显式指定，`Input`从42推导为 `int`。

API设计会影响模板调用的可读性。

## 15. 函数模板重载

可以同时存在普通函数和函数模板：

```cpp
void print_value(int value);

template <typename T>
void print_value(const T& value);
```

编译器会根据重载决议选择候选。

也可以有多个函数模板重载：

```cpp
template <typename T>
void inspect(const T& value);

template <typename T>
void inspect(const T* pointer);
```

重载决议可能变复杂。今天只观察几个明确案例，不尝试设计大量相互竞争的模板重载。

## 16. 模板错误可能延迟出现

定义模板：

```cpp
template <typename T>
void call_missing(const T& value) {
    value.not_existing();
}
```

如果模板从未实例化，一些编译器不一定立刻报告依赖于 `T`的错误。

当调用：

```cpp
call_missing(42);
```

实例化 `T=int`后，编译器才发现 `int`没有 `not_existing()`。

这就是模板错误信息经常出现在“实例化链”中的原因。

阅读报错时先找：

```text
模板在哪个类型上被实例化
第一个真正不成立的表达式
```

## 17. 类模板基本语法

```cpp
template <typename T>
class Box {
public:
    explicit Box(const T& value)
        : value_(value) {}

    const T& value() const noexcept {
        return value_;
    }

private:
    T value_;
};
```

使用：

```cpp
Box<int> int_box(42);
Box<std::string> text_box("audio");
```

`Box<int>`和 `Box<std::string>`是不同的具体类型。

不能写成不完整类型名：

```cpp
Box box; // 是否可行取决于CTAD，今天不依赖
```

今天统一显式写：

```cpp
Box<int>
```

## 19. 类内定义成员函数

```cpp
template <typename T>
class SimpleStack {
public:
    void push(const T& value) {
        elements_.push_back(value);
    }

    bool empty() const noexcept {
        return elements_.empty();
    }

private:
    std::vector<T> elements_;
};
```

这种写法最容易理解，适合短成员函数。

但大型类全部写在类体内会影响可读性，可以在同一个头文件中类外定义。

## 20. 类模板成员函数的类外定义

声明：

```cpp
template <typename T>
class SimpleStack {
public:
    void push(const T& value);
    const T& top() const;

private:
    std::vector<T> elements_;
};
```

类外定义：

```cpp
template <typename T>
void SimpleStack<T>::push(const T& value) {
    elements_.push_back(value);
}
```

返回类型也依赖 `T`：

```cpp
template <typename T>
const T& SimpleStack<T>::top() const {
    if (elements_.empty()) {
        throw std::runtime_error(
            "stack is empty"
        );
    }

    return elements_.back();
}
```

必须同时写：

```text
template <typename T>
SimpleStack<T>::
```

漏掉任意部分都会报错。

## 21. 为什么模板实现通常写在头文件

普通类可以：

```text
头文件放声明
cpp文件放实现
```

模板不同。编译某个使用点时，编译器通常需要同时看到：

```text
模板声明
+ 模板完整定义
+ 具体模板实参
```

才能生成实例。

如果头文件只有：

```cpp
template <typename T>
class Box {
public:
    T get() const;
};
```

而定义只在另一个 `.cpp`中，使用文件看不到定义，可能最终出现未定义符号链接错误。

因此常见做法：

```text
模板声明和实现都放.hpp
```

或者把实现放 `.tpp/.ipp`，再由头文件末尾包含：

```cpp
#include "box.tpp"
```

本阶段统一放在 `.hpp`中。

---

## 22. 隐式实例化

```cpp
template <typename T>
class Box {
    // ...
};

Box<int> first;
Box<double> second;
```

编译器看到使用后，根据需要生成 `Box<int>`和 `Box<double>`相关代码，这叫隐式实例化。

函数模板同理：

```cpp
square(3);    // square<int>
square(2.5);  // square<double>
```

不是所有成员函数一定立即全部生成；通常实际使用到相关成员时才要求其实例化成立。

---

## 23. 显式实例化定义

可以要求编译器在某个 `.cpp`中生成指定实例：

```cpp
template class ExplicitBox<int>;
template class ExplicitBox<double>;
```

函数模板：

```cpp
template int square<int>(int);
template double square<double>(double);
```

这叫显式实例化定义。

用途：

- 集中生成有限类型的模板代码；
- 减少多个翻译单元重复实例化；
- 隐藏部分实现；
- 控制二进制构建。

今天只完成小实验，不要求在所有模板项目中使用。

---

## 24. `extern template`

可以在头文件或使用点声明：

```cpp
extern template class ExplicitBox<int>;
```

它告诉当前翻译单元：

```text
这个显式实例会在其他翻译单元提供
```

然后某个 `.cpp`中必须有：

```cpp
template class ExplicitBox<int>;
```

如果只有 `extern template`却没有对应实例化定义，可能链接失败。

这是构建优化技术，不是今天写普通模板的默认选择。

---

## 25. 声明可见但定义不可见导致什么

典型情况：

```text
头文件：只有模板成员声明
template.cpp：有模板成员定义
main.cpp：实例化Template<int>
```

`template.cpp`自身不知道需要生成哪些具体类型，`main.cpp`又看不到实现，最终可能出现：

```text
Undefined symbols
undefined reference
```

修复方法：

1. 把模板定义移入头文件；或
2. 在 `.cpp`中显式实例化所有允许使用的具体类型。

不要看到链接错误就盲目增加 `#include`，先判断模板定义是否对实例化点可见。

```cpp
template <typename T = float>
```

可以写：

```cpp
FeatureBuffer<> default_buffer;
FeatureBuffer<double> double_buffer;
```

空尖括号仍然需要：

## 27. 非类型模板参数

模板参数不一定是类型：

```cpp
template <typename T, std::size_t Capacity>
class FixedBuffer {
private:
    std::array<T, Capacity> data_{};
};
```

使用：

```cpp
FixedBuffer<float, 128> buffer;
```

这里：

```text
T = float
Capacity = 128
```

`Capacity`是编译期值，不是运行时构造函数参数。

因此：

```cpp
std::size_t size = read_from_user();
FixedBuffer<float, size> buffer; // 不可以，size不是编译期常量
```

运行时长度应考虑 `vector`。

## 28. 模板静态成员

```cpp
template <typename T>
class Counter {
public:
    inline static std::size_t count = 0;

```

不同实例通常有各自的静态成员：

```text
Counter<int>::count
Counter<double>::count
```

它们不是同一个变量。

今天只做观察，综合项目不需要依赖模板静态全局计数。

## 29. `static_assert`基础约束

需要：

```cpp
#include <type_traits>
```

例如只允许算术类型：

```cpp
template <typename T>
class NumericBuffer {
    static_assert(
        std::is_arithmetic<T>::value,
        "T must be an arithmetic type"
    );
};
```

当实例化：

```cpp
NumericBuffer<std::string>
```

编译期报错并显示自定义信息。

`static_assert`不等同于运行时 `if`：

```text
static_assert -> 编译期条件
if            -> 运行时条件
```

## 30. `std::is_arithmetic`

```cpp
std::is_arithmetic<T>::value
```

对常见整数和浮点类型为 `true`。

C++17也可以写：

```cpp
std::is_arithmetic_v<T>
```

今天推荐较简洁的 `_v`形式：

```cpp
static_assert(
    std::is_arithmetic_v<T>,
    "T must be arithmetic"
);
```

这只是基础类型特征。复杂约束后续再学习。

## 31. 特化只要求认识

主模板：

```cpp
template <typename T>
class Formatter;
```

针对某个具体类型提供不同实现叫全特化：

```cpp
template <>
class Formatter<bool> {
};
```

类模板还可以偏特化一部分参数组合。

今天不要在 `FeatureBatch`中为不同数值类型写特化；保持统一泛型接口，用测试验证类型行为。

函数模板一般不使用偏特化，常通过重载实现差异。此处只记概念。

## 32. 模板的代码膨胀

如果模板在许多类型上实例化，可能生成多份机器代码：

```text
FeatureBatch<float>
FeatureBatch<double>
FeatureBatch<int>
```

这称为代码膨胀风险。

不要因此拒绝模板。标准库大量使用模板。正确做法是：

- 对确实需要的类型实例化；
- 避免无意义的类型组合；
- 性能和体积有证据后再优化；
- 可在合适场景使用显式实例化。

---

## 33. 模板不是运行时多态

模板通常属于编译期多态：

```text
编译时选择和生成具体类型代码
```

虚函数属于运行时多态：

```text
运行时通过基类接口选择实际对象行为
```

两者可以共同使用：

- 模板用于泛型容器和数值类型；
- 虚函数用于不同推理后端的运行时切换。

不要认为学了模板就不再需要虚函数。

## 34. 常见错误

### 错误1：漏写模板头

类外定义前必须有：

```cpp
template <typename T>
```

### 错误2：漏写 `<T>`

```cpp
SimpleStack<T>::push
```

不能写成：

```cpp
SimpleStack::push
```

### 错误3：模板实现只放 `.cpp`

使用点看不到定义可能链接失败。

### 错误4：以为返回值能推导所有模板参数

通常不能依靠接收变量反推模板参数。

### 错误5：不同实参类型导致同一个 `T`推导冲突

需要统一类型、显式指定或重新设计模板。

### 错误6：认为模板支持任何类型

类型必须满足模板内部表达式需求。

### 错误7：返回指向临时参数的引用

模板不延长生命周期。

### 错误8：用运行时变量作为非类型模板实参

非类型模板参数通常要求编译期常量。

### 错误9：只有 `extern template`没有显式定义

可能出现链接错误。

### 错误10：报错很长就只看最后一行

应寻找第一次实例化位置和第一个不成立表达式。

### 错误11：测试只使用一种类型

无法证明泛型代码在预期类型集合上成立。

### 错误12：过早使用复杂SFINAE

今天先用清晰的接口和 `static_assert`。

## 47. 如何阅读模板报错

模板报错可能包含很多层：

```text
requested here
in instantiation of...
candidate function not viable
no matching operator
```

建议顺序：

1. 找你自己代码中触发模板调用的位置；
2. 找“实例化为哪个具体类型”；
3. 找模板内部第一个失败表达式；
4. 检查类型是否满足操作要求；
5. 检查是否推导冲突；
6. 如果编译成功但链接失败，检查定义可见性和显式实例化文件。

不要只从最后一行开始猜。

## 48. Sanitizer能验证什么

ASan/UBSan可帮助发现模板实例生成后的运行时问题：

- 越界；
- 悬空引用；
- 整数相关部分未定义行为；
- 资源生命周期错误。

但不能发现或不能替代：

- 模板推导设计不合理；
- 模板定义不可见造成的编译/链接问题；
- 未实例化类型中的潜在错误；
- 代码膨胀；
- 约束表达不清；
- 类型语义错误，例如整数平均值截断。

因此需要：

```text
多类型编译测试
+ 单元测试
+ 编译失败案例分析
+ ASan/UBSan
```

## 55. 最终速记

```text
函数模板：一份函数结构用于多种满足要求的类型

类模板：一份类结构生成不同具体类型

template <typename T>：T是类型模板参数

自动推导：从函数实参推导T
显式实参：function<double>(...)

Class<int>与Class<double>是不同具体类型

类外定义：
template <typename T>
Return Class<T>::member(...)

模板定义通常放头文件，因为实例化点需要看到完整定义

隐式实例化：使用时按需生成
显式实例化：template class Class<int>;

非类型模板参数：template<typename T, size_t N>

static_assert：编译期约束

模板不会自动解决生命周期、越界和业务语义问题
```
