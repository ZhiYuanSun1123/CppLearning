## 3. 什么是封装

封装不是简单地“把变量放进类里”，而是：

> 隐藏对象内部状态，只通过受控的公开接口访问和修改，从而维护对象始终处于合法状态。

没有封装：

```cpp
class AudioConfig {
public:
    int sample_rate;
    int channels;
};
```

外部可以写：

```cpp
AudioConfig config;
config.sample_rate = -16000;
config.channels = 0;
```

这些状态对于音频配置通常不合法。

封装后：

```cpp
#include <stdexcept>

class AudioConfig {
public:
    AudioConfig(
        int sample_rate,
        int channels
    )
        : sample_rate_(sample_rate),
          channels_(channels) {
        validate();
    }

    int sample_rate() const {
        return sample_rate_;
    }

    int channels() const {
        return channels_;
    }

    void set_sample_rate(int value) {
        if (value <= 0) {
            throw std::runtime_error(
                "采样率必须大于0"
            );
        }

        sample_rate_ = value;
    }

private:
    void validate() const {
        if (sample_rate_ <= 0) {
            throw std::runtime_error(
                "采样率必须大于0"
            );
        }

        if (channels_ <= 0) {
            throw std::runtime_error(
                "声道数必须大于0"
            );
        }
    }

    int sample_rate_;
    int channels_;
};
```

外部只能通过公开接口：

```cpp
AudioConfig config(16000, 1);

std::cout
    << config.sample_rate()
    << '\n';
```

不能直接破坏内部状态：

```cpp
config.sample_rate_ = -1; // 编译错误
```

## 4. 对象不变量

对象不变量是：

> 对象处于有效状态时必须始终满足的条件。

对 `AudioConfig` 而言：

```text
sample_rate > 0
channels > 0
```

构造函数应建立不变量：

```cpp
AudioConfig(int sample_rate, int channels)
    : sample_rate_(sample_rate),
      channels_(channels) {
    validate();
}
```

所有修改函数应维持不变量：

```cpp
void set_sample_rate(int value) {
    if (value <= 0) {
        throw std::runtime_error(
            "无效采样率"
        );
    }

    sample_rate_ = value;
}
```

只读函数不破坏不变量：

```cpp
int sample_rate() const {
    return sample_rate_;
}
```

封装的真正价值就是让类自己负责这些规则，而不是要求所有调用者都记住。

## 5. public、private和protected

### `public`

类外可以访问：

```cpp
public:
    int sample_rate() const;
```

### `private`

只有当前类自己的成员函数和友元可以直接访问：

```cpp
private:
    int sample_rate_;
```

派生类也不能直接访问基类的 `private` 成员。

### `protected`

类外不能直接访问，但派生类可以访问：

```cpp
protected:
    std::string name_;
```

示例：

```cpp
class Model {
protected:
    std::string name_;
};

class AudioModel : public Model {
public:
    void print_name() const {
        std::cout << name_ << '\n';
    }
};
```

但工程中不应为了方便就把所有成员改成 `protected`。推荐：

```text
数据优先private
派生类通过protected或public成员函数访问
只有确实需要派生类直接访问时才使用protected
```

## 6. 什么是组合

组合表示：

> 一个类把另一个类的对象作为自己的成员。

组合常用于表达 `has-a`：

```text
AudioPipeline has an AudioDecoder
音频流水线拥有一个音频解码器
```

例如：

```cpp
#include <iostream>
#include <string>

class AudioDecoder {
public:
    AudioDecoder(
        const std::string& format
    )
        : format_(format) {
    }

    void decode() const {
        std::cout
            << "Decode format: "
            << format_
            << '\n';
    }

private:
    std::string format_;
};

class AudioPipeline {
public:
    AudioPipeline(
        const std::string& format
    )
        : decoder_(format) {
    }

    void run() const {
        decoder_.decode();
        std::cout
            << "Pipeline finished\n";
    }

private:
    AudioDecoder decoder_;
};
```

使用：

```cpp
AudioPipeline pipeline("wav");
pipeline.run();
```

关系：

```text
AudioPipeline
      │
      │ 拥有
      ▼
AudioDecoder
```

`AudioPipeline` 不是一种 `AudioDecoder`，而是使用一个 `AudioDecoder` 完成工作，所以组合合适。

## 7. 组合对象的初始化

成员对象应在初始化列表中构造：

```cpp
class AudioPipeline {
public:
    AudioPipeline(
        const std::string& format
    )
        : decoder_(format) {
    }

private:
    AudioDecoder decoder_;
};
```

不能先创建一个无法默认构造的成员，再在构造函数体中“重新构造”：

```cpp
AudioPipeline(
    const std::string& format
) {
    decoder_ = AudioDecoder(format);
}
```

这段代码首先要求 `decoder_` 能完成默认构造，然后再赋值。若 `AudioDecoder` 没有默认构造函数，会直接编译失败。

正确方式是：

```cpp
: decoder_(format)
```

让成员第一次创建时就获得正确参数。

## 8. 组合对象的生命周期

```cpp
class Decoder {
public:
    Decoder() {
        std::cout << "Construct Decoder\n";
    }

    ~Decoder() {
        std::cout << "Destroy Decoder\n";
    }
};

class Pipeline {
public:
    Pipeline() {
        std::cout << "Construct Pipeline\n";
    }

    ~Pipeline() {
        std::cout << "Destroy Pipeline\n";
    }

private:
    Decoder decoder_;
};
```

创建：

```cpp
Pipeline pipeline;
```

顺序：

```text
Construct Decoder
Construct Pipeline
Destroy Pipeline
Destroy Decoder
```

原因：

```text
构造完整Pipeline之前
必须先构造它的成员decoder_

销毁Pipeline时
先执行Pipeline析构函数体
再销毁成员decoder_
```

成员按声明顺序构造，按相反顺序析构。

## 9. 什么是继承

继承用于表达：

> 一个新类型是已有类型的一种更具体形式。

即 `is-a`：

```text
AudioModel is a Model
音频模型是一种模型
```

基础语法：

```cpp
class Model {
public:
    Model(const std::string& name)
        : name_(name) {
    }

    const std::string& name() const {
        return name_;
    }

private:
    std::string name_;
};

class AudioModel : public Model {
public:
    AudioModel(
        const std::string& name,
        int sample_rate
    )
        : Model(name),
          sample_rate_(sample_rate) {
    }

    int sample_rate() const {
        return sample_rate_;
    }

private:
    int sample_rate_;
};
```

其中：

```cpp
class AudioModel : public Model
```

表示 `AudioModel` 公有继承 `Model`。

`Model` 是基类，`AudioModel` 是派生类。

## 10. 派生类初始化基类

派生类构造函数需要在初始化列表中调用基类构造函数：

```cpp
AudioModel(
    const std::string& name,
    int sample_rate
)
    : Model(name),
      sample_rate_(sample_rate) {
}
```

这里：

```cpp
Model(name)
```

负责构造基类部分。

如果基类没有默认构造函数，而派生类又没有明确调用合适的基类构造函数，就会编译失败。

例如基类只有：

```cpp
Model(const std::string& name);
```

派生类错误写法：

```cpp
AudioModel(int sample_rate)
    : sample_rate_(sample_rate) {
}
```

编译器会尝试调用：

```cpp
Model()
```

但它不存在，所以失败。

## 11. 继承中的访问权限

假设：

```cpp
class Model {
public:
    const std::string& name() const {
        return name_;
    }

private:
    std::string name_;
};
```

派生类可以调用基类的 `public` 函数：

```cpp
void AudioModel::print() const {
    std::cout << name() << '\n';
}
```

但不能直接访问：

```cpp
std::cout << name_; // 编译错误
```

因为 `name_` 是基类 `private` 成员。

这通常是好事：基类仍然控制自己的内部状态。

## 12. public继承的基础含义

今天只使用：

```cpp
class Derived : public Base
```

在公有继承下，基类的公开接口仍然是派生类的公开接口：

```cpp
AudioModel model(
    "audio-classifier",
    16000
);

std::cout << model.name() << '\n';
```

`name()` 定义在 `Model` 中，但 `AudioModel` 对象可以调用。

`private`继承和`protected`继承今天不学习。它们表达的是不同的实现关系，不适合刚开始判断 `is-a`。

## 13. 基类和派生类的构造析构顺序

```cpp
class Base {
public:
    Base() {
        std::cout << "Construct Base\n";
    }

    ~Base() {
        std::cout << "Destroy Base\n";
    }
};

class Derived : public Base {
public:
    Derived() {
        std::cout << "Construct Derived\n";
    }

    ~Derived() {
        std::cout << "Destroy Derived\n";
    }
};
```

创建：

```cpp
Derived object;
```

输出：

```text
Construct Base
Construct Derived
Destroy Derived
Destroy Base
```

原因：

```text
构造派生类之前
先建立基类部分

销毁时
先销毁派生类部分
再销毁基类部分
```

这同样遵循依赖关系和逆序销毁规则。

## 14. 同时存在基类和成员对象时的顺序

```cpp
class Base {
public:
    Base() {
        std::cout << "Base\n";
    }

    ~Base() {
        std::cout << "~Base\n";
    }
};

class Member {
public:
    Member() {
        std::cout << "Member\n";
    }

    ~Member() {
        std::cout << "~Member\n";
    }
};

class Derived : public Base {
public:
    Derived() {
        std::cout << "Derived\n";
    }

    ~Derived() {
        std::cout << "~Derived\n";
    }

private:
    Member member_;
};
```

构造顺序：

```text
1. Base基类部分
2. Member成员对象
3. Derived构造函数体
```

析构顺序：

```text
1. Derived析构函数体
2. Member成员对象
3. Base基类部分
```

完整输出：

```text
Base
Member
Derived
~Derived
~Member
~Base
```

## 15. is-a与has-a

这是今天最重要的设计判断。

### `is-a`：可能适合继承

```text
AudioModel is a Model
音频模型是一种模型
```

```text
WavDecoder is a Decoder
WAV解码器是一种解码器
```

### `has-a`：适合组合

```text
AudioPipeline has a Decoder
音频流水线拥有一个解码器
```

```text
InferenceService has a Model
推理服务拥有一个模型
```

错误判断：

```text
AudioPipeline is a Decoder
```

音频流水线不是一种解码器，它只是使用解码器，所以不应该为了复用 `decode()` 而继承 `Decoder`。

## 16. 为什么通常优先考虑组合

组合通常有这些优势：

- 关系更直观；
- 依赖容易替换；
- 类之间耦合更低；
- 不会把不需要的基类接口暴露出去；
- 更容易单独测试成员组件；
- 不容易形成复杂继承层次；
- 对成员对象生命周期管理清楚。

例如：

```cpp
class AudioPipeline {
public:
    AudioPipeline(
        const std::string& format
    )
        : decoder_(format) {
    }

private:
    AudioDecoder decoder_;
};
```

这里直接使用构造参数初始化成员对象，不涉及尚未学习的拷贝语义。今天重点看“流水线拥有解码器”的关系。

简单规则：

> 如果只是想复用某个对象的功能，优先考虑把它作为成员，而不是继承它。

继承适合表达稳定、真实的类型分类，而不是单纯减少重复代码。

## 17. 什么时候使用继承

基础继承通常需要同时满足：

1. 派生类确实是基类的一种；
2. 派生类能够合理继承基类公开接口；
3. 基类代表稳定的共同概念；
4. 派生类不会破坏基类规定的行为；
5. 未来确实需要把这些类型作为同一类概念使用。

例如：

```text
Model
├── AudioModel
├── TextModel
└── VisionModel
```

这些都可能是模型。

但真正通过统一接口动态调用不同实现，需要虚函数和运行时多态，将在下一工作日学习。

## 18. 不要为了复用几行代码滥用继承

错误设计：

```cpp
class Logger {
public:
    void log(
        const std::string& message
    ) const {
        std::cout << message << '\n';
    }
};

class AudioModel : public Logger {
};
```

`AudioModel` 并不是一种 `Logger`，它只是需要使用日志功能。

组合更合理：

```cpp
class AudioModel {
public:
    void load() {
        logger_.log("Load model");
    }

private:
    Logger logger_;
};
```

关系变成：

```text
AudioModel has a Logger
```

## 22. 练习3：基础继承Model

文件：`03_basic_inheritance.cpp`

```cpp
#include <iostream>
#include <stdexcept>
#include <string>

class Model {
public:
    Model(const std::string& name)
        : name_(name) {
        if (name_.empty()) {
            throw std::runtime_error(
                "模型名称不能为空"
            );
        }
    }

    const std::string& name() const {
        return name_;
    }

    void print_base_info() const {
        std::cout
            << "Model: "
            << name_
            << '\n';
    }

private:
    std::string name_;
};

class AudioModel : public Model {
public:
    AudioModel(
        const std::string& name,
        int sample_rate
    )
        : Model(name),
          sample_rate_(sample_rate) {
        if (sample_rate_ <= 0) {
            throw std::runtime_error(
                "采样率必须大于0"
            );
        }
    }

    int sample_rate() const {
        return sample_rate_;
    }

    void print_audio_info() const {
        print_base_info();

        std::cout
```

## 29. 常见错误

### 错误1：所有成员都写成public

这会使类无法控制自己的有效状态。

### 错误2：成员对象在构造函数体中赋值

应该优先在初始化列表中直接构造。

### 错误3：派生类忘记初始化基类

基类没有默认构造函数时会编译失败。

### 错误4：直接访问基类private成员

应通过基类公开或受保护接口访问。

### 错误5：为了复用一个函数就继承

先判断是否只是 `has-a` 或 `uses-a`。

### 错误6：把继承理解成复制基类对象

派生类对象内部包含基类部分，但不是通过普通拷贝构造产生一个独立基类对象。

### 错误7：误判构造顺序

总顺序是：

```text
基类
成员对象
派生类构造函数体
```

析构相反。
