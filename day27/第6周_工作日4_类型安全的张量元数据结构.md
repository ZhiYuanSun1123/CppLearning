# 第6周·工作日4：实现类型安全的张量元数据结构

## 0. 今天要解决的问题

在 AI 部署程序中，张量不只有一段数值，还需要描述这些数值：

```text
名称
形状 shape
数据类型 dtype
布局 layout
设备 device
```

如果全部使用 `int`、`std::string` 和公开成员，下面这些错误都可能进入系统：

```cpp
// 这些值的含义不清晰，也很容易传错。
TensorMetadata metadata(
    "audio_features",
    {1, 3000, 80},
    2,
    1,
    -5
);
```

今天要把它重构成：

```cpp
TensorMetadata metadata(
    "audio_features",
    TensorShape({1, 3000, 80}),
    DataType::float32,
    TensorLayout::batch_time_feature,
    Device{DeviceType::cpu, 0}
);
```

目标不是实现真正的张量计算库，而是实现一个：

> 能准确描述张量、阻止无效状态、能够安全计算内存需求的 C++ 元数据模块。

今天完成后，你应该能够：

1. 解释“类型安全”到底安全在哪里；
2. 使用 `enum class`代替无含义的整数和字符串；
3. 使用类封装形状并维护不变量；
4. 区分标量、空张量和普通张量；
5. 安全计算元素数量，避免整数溢出；
6. 根据数据类型安全计算理论字节数；
7. 使用 `std::optional`表达“可能无法计算”；
8. 使用 `std::variant<Value, Error>`返回详细校验错误；
9. 为张量元数据补充单元测试；
10. 形成一个可被后续 ONNX Runtime、TensorRT 和 AudioLLM 项目复用的接口。

## 4. 什么是张量元数据

元数据就是“描述数据的数据”。

下面是一份音频特征张量：

```text
名称：audio_features
形状：[1, 3000, 80]
类型：float32
布局：batch_time_feature
设备：cpu:0
```

真正的张量数值可能有：

```text
1 × 3000 × 80 = 240000个元素
```

但是 `TensorMetadata`今天不保存这些浮点数，只保存描述信息。

可以把它理解成快递箱外面的标签：

```text
标签不是箱内货物
但标签告诉系统如何解释箱内货物
```

在推理部署中，元数据错误会产生严重后果：

- 把 `float32`缓冲区当作 `int8`读取；
- 把 `[batch, time, feature]`当作 `[batch, feature, time]`；
- 计算错误的缓冲区字节数；
- 使用无效设备编号；
- 把模型要求的输入形状传错。

所以元数据不是“随便记录几个字符串”，而是接口契约的一部分。

## 5. 什么是类型安全

类型安全并不代表程序绝对不会出错。这里主要表示：

> 让编译器帮助区分不同概念，使无意义的值和错误组合更难进入程序。

不安全的设计：

```cpp
struct TensorMetadata {
    std::string name;
    std::vector<int> shape;
    int data_type;
    int layout;
    int device;
};
```

调用者可能写：

```cpp
metadata.data_type = 99;
metadata.layout = -1;
metadata.device = 44100;
```

编译器无法理解这些整数的业务含义。

类型安全的方向：

```cpp
enum class DataType {
    float32,
    float16,
    int32,
    int8,
    boolean
};

enum class TensorLayout {
    contiguous,
    batch_channel_time,
    batch_time_feature
};
```

现在不能把布局直接赋给数据类型：

```cpp
DataType type = DataType::float32;

// 编译错误：两者是不同类型
// type = TensorLayout::contiguous;
```

类型安全的收益包括：

1. 编译期阻止一部分错误；
2. 函数参数含义更清楚；
3. IDE补全更准确；
4. `switch`更容易检查是否遗漏情况；
5. 测试可以围绕明确的不变量展开。

## 6. 用 `enum class`表示数据类型

在 `include/data_type.hpp`中设计：

```cpp
#ifndef DATA_TYPE_HPP
#define DATA_TYPE_HPP

#include <cstddef>
#include <optional>
#include <string_view>

enum class DataType {
    float32,
    float16,
    int32,
    int8,
    boolean
};

[[nodiscard]] std::string_view to_string(
    DataType type
) noexcept;

[[nodiscard]] std::optional<std::size_t>
bytes_per_element(DataType type) noexcept;

#endif
```

这里：

```cpp
DataType::float32
```

表达的是一个有明确含义的类型，不是魔法整数。

`to_string()`用于日志：

```cpp
std::cout << to_string(DataType::float32);
```

输出：

```text
float32
```

`bytes_per_element()`用于查询每个元素占用的字节数：

```text
float32 → 4
float16 → 2
int32   → 4
int8    → 1
boolean → 1（本练习约定）
```

这里使用 `optional<size_t>`，是为了防御通过强制转换产生的非法枚举值：

```cpp
const auto invalid = static_cast<DataType>(100);
const auto bytes = bytes_per_element(invalid);

if (!bytes) {
    // 无法识别该数据类型
}
```

注意：不同真实推理框架对布尔类型的存储实现可能不同。今天统一约定为1字节，并在文档中明确这个契约。

## 7. `std::string_view`为什么适合 `to_string()`

枚举转换返回的是固定字符串：

```cpp
"float32"
"float16"
"int32"
```

它们是字符串字面量，生命周期贯穿整个程序，因此可以返回：

```cpp
std::string_view
```

示例：

```cpp
std::string_view to_string(DataType type) noexcept {
    switch (type) {
        case DataType::float32:
            return "float32";
        case DataType::float16:
            return "float16";
        case DataType::int32:
            return "int32";
        case DataType::int8:
            return "int8";
        case DataType::boolean:
            return "boolean";
    }

    return "unknown";
}
```

这里的 `string_view`不拥有字符串，而只是观察静态字符串字面量，因此是安全的。

危险示例：

```cpp
std::string_view wrong() {
    std::string local = "float32";
    return local; // 返回后local被销毁，string_view悬空
}
```

今天只在字符串字面量场景使用 `string_view`。

## 9. 设备元数据不是硬件设计

在 `include/device.hpp`中设计：

```cpp
enum class DeviceType {
    cpu,
    accelerator
};

class Device {
public:
    Device(DeviceType type, int index);

    [[nodiscard]] DeviceType type() const noexcept;
    [[nodiscard]] int index() const noexcept;

private:
    DeviceType type_;
    int index_;
};
```

这里的设备只是逻辑位置：

```text
cpu:0
accelerator:0
accelerator:1
```

你不需要知道芯片内部电路，也不需要真的拥有加速卡。

需要规定不变量，例如：

```text
设备编号不能小于0
```

非法示例：

```cpp
Device(DeviceType::accelerator, -1);
Device(DeviceType::cpu, 3);
```

构造函数可以对非法值抛出 `std::invalid_argument`。这是创建配置对象时立即拒绝程序员错误的合理场景。

## 10. 为什么形状不能只是公开的 `vector<int>`

下面的设计虽然简单，但无法维护规则：

```cpp
struct TensorMetadata {
    std::vector<int> shape;
};
```

调用者可以随时写：

```cpp
metadata.shape.push_back(-5);
metadata.shape.clear();
metadata.shape[100] = 3;
```

其中：

- 负维度通常不适合表示已经具体化的运行时张量；
- 越界访问是未定义行为；
- 随意修改会破坏已经验证的元数据。

所以建立：

```cpp
class TensorShape
```

由它负责：

- 保存维度；
- 提供只读访问；
- 检查轴索引；
- 计算 rank；
- 安全计算元素总数；
- 阻止外部绕过规则随意修改内部容器。

## 11. `TensorShape`接口设计

在 `include/tensor_shape.hpp`中设计：

```cpp
#ifndef TENSOR_SHAPE_HPP
#define TENSOR_SHAPE_HPP

#include <cstddef>
#include <initializer_list>
#include <optional>
#include <vector>

class TensorShape {
public:
    TensorShape();

    explicit TensorShape(
        std::vector<std::size_t> dimensions
    );

    TensorShape(
        std::initializer_list<std::size_t> dimensions
    );

    [[nodiscard]] std::size_t rank() const noexcept;

    [[nodiscard]] bool is_scalar() const noexcept;

    [[nodiscard]] bool is_empty_tensor() const noexcept;

    [[nodiscard]] const std::vector<std::size_t>&
    dimensions() const noexcept;

    [[nodiscard]] std::size_t at(
        std::size_t axis
    ) const;

    [[nodiscard]] std::optional<std::size_t>
    numel() const noexcept;

private:
    std::vector<std::size_t> dimensions_;
};

#endif
```

### 为什么返回 `const vector&`

```cpp
const std::vector<std::size_t>& dimensions() const;
```

这样：

- 不复制整个维度数组；
- 调用者可以读取；
- 调用者不能通过这个接口修改内部维度；
- 对象仍然维护自己的不变量。

错误方向：

```cpp
std::vector<std::size_t>& dimensions();
```

它会把可修改引用暴露出去：

```cpp
shape.dimensions().clear();
```

这会绕过类的检查。

## 12. rank、dimension和axis分别是什么

对于：

```text
shape = [2, 3, 80]
```

含义：

```text
rank = 3

axis 0的dimension = 2
axis 1的dimension = 3
axis 2的dimension = 80
```

对应代码：

```cpp
TensorShape shape({2, 3, 80});

shape.rank(); // 3
shape.at(0);  // 2
shape.at(1);  // 3
shape.at(2);  // 80
```

这里建议使用：

```cpp
dimensions_.at(axis)
```

而不是：

```cpp
dimensions_[axis]
```

因为 `at()`会在越界时抛出 `std::out_of_range`，更适合学习阶段发现错误。

## 13. 标量、空形状和空张量

这是今天最容易混淆的地方。

### 标量

零阶张量的形状写作：

```text
[]
```

它没有轴，但包含一个标量值：

```text
rank = 0
numel = 1
```

代码：

```cpp
TensorShape scalar_shape;
```

### 空张量

只要某个维度是0：

```text
[2, 0, 80]
```

元素数量就是：

```text
2 × 0 × 80 = 0
```

它是一个合法的空张量：

```text
rank = 3
numel = 0
```

所以：

```text
shape为空 []
不等于
张量元素数量为0
```

本练习约定：

```text
[]          → 标量，1个元素
[0]         → 一维空张量，0个元素
[2, 0, 80] → 三维空张量，0个元素
```

## 14. 为什么 `numel()`不能直接连乘

直观代码：

```cpp
std::size_t count = 1;

for (std::size_t dimension : dimensions_) {
    count *= dimension;
}
```

问题是整数可能溢出。

假设 `size_t`能够表示的最大值是：

```cpp
std::numeric_limits<std::size_t>::max()
```

当乘法结果超过它时，无符号整数会按模运算回绕，得到一个错误的小值，而且程序不一定报错。

所以必须在乘法前检查：

```cpp
if (count != 0 &&
    dimension > max_value / count) {
    return std::nullopt;
}

count *= dimension;
```

判断依据：

```text
如果 dimension > max / count
那么 count × dimension 一定超过max
```

这里返回：

```cpp
std::optional<std::size_t>
```

含义：

```text
有值    → 成功算出元素数量
nullopt → 乘法会溢出，无法可靠计算
```

## 15. 安全 `numel()`参考逻辑

下面是学习示例，不要直接复制成练习答案，先自己实现：

```cpp
std::optional<std::size_t>
TensorShape::numel() const noexcept {
    std::size_t count = 1;

    for (const std::size_t dimension
         : dimensions_) {
        if (dimension == 0) {
            return std::size_t{0};
        }

        const std::size_t maximum =
            std::numeric_limits<std::size_t>::max();

        if (dimension > maximum / count) {
            return std::nullopt;
        }

        count *= dimension;
    }

    return count;
}
```

空维度数组会保持：

```cpp
count == 1
```

因此标量的元素数是1。

### 一个细节

如果形状里存在0，即使其他维度巨大，数学结果也是0。上面遇到0直接返回0，避免后续没有意义的溢出判断。

## 16. 为什么使用 `size_t`表示具体维度

运行时已经具体化的维度数量不能为负，因此使用：

```cpp
std::size_t
```

它也是标准容器长度使用的类型。

但是读取外部文本时不能直接把负数转换成 `size_t`：

```cpp
int input = -1;
std::size_t dimension =
    static_cast<std::size_t>(input);
```

这会变成一个非常大的无符号整数。

正确流程应该是：

```text
先使用有符号类型解析
        ↓
检查是否小于0
        ↓
通过后再转成size_t
```

今天的核心类接收已经验证过的具体维度；从字符串解析形状留到扩展练习。

## 18. 为什么成员要设为 `private`

公开成员：

```cpp
metadata.name = "";
metadata.shape = invalid_shape;
```

可能让一个原本合法的对象变成非法状态。

私有成员配合构造函数：

```text
创建对象时统一检查
创建成功后保持不变量
外部只能通过只读接口观察
```

这叫作：

> 让非法状态难以表示。

今天至少维护以下不变量：

1. 张量名称不能为空；
2. 设备信息必须有效；
3. 数据类型必须是已知类型；
4. 形状元素数不能溢出；
5. 字节数计算不能溢出。

## 19. 如何安全计算 `byte_size()`

公式是：

```text
字节数 = 元素数量 × 每个元素的字节数
```

但两个步骤都可能失败：

```text
numel()可能溢出
DataType可能是非法枚举值
最终乘法也可能溢出
```

建议逻辑：

```cpp
const auto element_count = shape_.numel();

if (!element_count) {
    return std::nullopt;
}

const auto element_bytes =
    bytes_per_element(data_type_);

if (!element_bytes) {
    return std::nullopt;
}
```

然后在乘法前检查：

```cpp
if (*element_count != 0 &&
    *element_bytes > maximum / *element_count) {
    return std::nullopt;
}
```

注意：

```cpp
std::optional<std::size_t>{0}
```

是“成功算出结果为0”，不是失败。

判断成功要写：

```cpp
if (element_count.has_value())
```

不要用数值是否为0判断成功失败。

## 20. `optional<size_t>{0}`和 `nullopt`的区别

```cpp
std::optional<std::size_t> first = 0;
std::optional<std::size_t> second = std::nullopt;
```

二者完全不同：

```text
first：有值，结果就是0
second：没有结果
```

验证：

```cpp
first.has_value();  // true
second.has_value(); // false
```

在张量中：

```text
[2, 0, 80]
```

是合法空张量，所以：

```cpp
numel() == optional<size_t>{0}
```

而溢出时：

```cpp
numel() == std::nullopt
```

## 21. 构造异常和错误返回如何选择

两类错误应该区分。

### 程序员直接构造非法对象

```cpp
TensorMetadata(
    "",
    TensorShape({1, 80}),
    DataType::float32,
    TensorLayout::batch_time_feature,
    Device(DeviceType::cpu, 0)
);
```

空名称违反类的不变量。构造函数可以抛出：

```cpp
std::invalid_argument
```

### 外部输入可能失败

例如从配置文件解析：

```text
name=audio
shape=1,-5,80
dtype=float128
```

外部输入失败是预期情况，更适合返回：

```cpp
std::variant<TensorMetadata, MetadataError>
```

因此可以使用两层设计：

```text
TensorMetadata构造函数
    维护内部不变量

parse_tensor_metadata()
    把外部文本转换成对象并返回详细错误
```

## 22. 详细错误类型

在 `include/metadata_error.hpp`中设计：

```cpp
#ifndef METADATA_ERROR_HPP
#define METADATA_ERROR_HPP

#include <cstddef>
#include <string>

enum class MetadataErrorCode {
    empty_name,
    invalid_dimension,
    invalid_data_type,
    invalid_layout,
    invalid_device,
    element_count_overflow,
    byte_size_overflow,
    rank_layout_mismatch
};

struct MetadataError {
    MetadataErrorCode code;
    std::string message;
    std::size_t axis;
};

#endif
```

并定义：

```cpp
using MetadataResult = std::variant<
    TensorMetadata,
    MetadataError
>;
```

`axis`只在维度错误时有意义。为了避免用魔法值表达“不适用”，更类型安全的设计是：

```cpp
std::optional<std::size_t> axis;
```

推荐最终写成：

```cpp
struct MetadataError {
    MetadataErrorCode code;
    std::string message;
    std::optional<std::size_t> axis;
};
```

这正好复用昨天的 `optional`。

## 23. 布局与rank校验

本练习可以制定简单契约：

```text
contiguous
    接受任意rank

batch_channel_time
    要求rank == 3

batch_time_feature
    要求rank == 3
```

校验函数：

```cpp
[[nodiscard]] std::optional<MetadataError>
validate_layout_rank(
    const TensorShape& shape,
    TensorLayout layout
);
```

返回语义：

```text
nullopt
    没有发现错误

MetadataError
    发现布局和rank不匹配
```

这里 `optional<Error>`非常适合，因为只有两种结果：

```text
无错误
或
一个错误
```

如果要返回成功对象或错误，则使用：

```cpp
variant<TensorMetadata, MetadataError>
```

## 25. 为什么元数据对象应该尽量不可变

假设对象创建后可以任意修改：

```cpp
metadata.set_shape({1, 80});
metadata.set_layout(
    TensorLayout::batch_time_feature
);
```

修改后可能出现：

```text
rank = 2
layout要求rank = 3
```

每个 setter 都必须重新验证整个对象，复杂度会快速上升。

学习阶段推荐：

- 构造时一次性传入完整状态；
- 构造成功后只提供只读访问器；
- 需要不同元数据时，创建新对象；
- 不提供随意改变成员的 setter。

这种设计更接近值对象：

```cpp
const TensorMetadata input_metadata(...);
```

它适合在推理请求、模型描述和缓存键中传递。

## 28. 常见错误

### 错误1：用字符串表示所有概念

```cpp
metadata.dtype = "folat32";
```

拼写错误只能运行时发现。

### 错误2：用一个 `int`表示不同业务概念

```cpp
void configure(int type, int layout, int device);
```

调用时非常容易调换顺序。

### 错误3：认为空shape就是空张量

```text
[]是标量形状，numel为1
```

### 错误4：直接连乘维度

可能发生无符号整数溢出。

### 错误5：把 `nullopt`和结果0混为一谈

空张量元素数是合法的0；溢出才是没有结果。

### 错误6：使用 `operator[]`访问不可信axis

越界可能产生未定义行为，外部输入优先使用 `at()`。

### 错误7：返回可修改的内部容器引用

会让调用者绕过类的不变量。

### 错误8：从负数直接转换为 `size_t`

负数会变成巨大的无符号数。

### 错误9：认为 `enum class`不可能非法

强制转换仍然能制造未列出的枚举值。

### 错误10：布局由形状自动推断

相同数字可能有不同轴语义。

### 错误11：所有失败都抛异常

外部配置错误通常是预期失败，详细错误返回更方便处理。

### 错误12：所有失败都返回 `false`

调用方无法知道是名称、维度、布局还是溢出问题。

### 错误13：手写不必要的资源管理代码

本项目成员已经由标准库管理，不需要裸 `new/delete`。

### 错误14：为了“类型安全”创建过多薄包装

类型设计应该解决真实的混淆问题，不能让接口难以使用。

## 45. 和求职技术栈的联系

```text
模型输入输出描述
shape/dtype/layout检查
缓冲区大小计算
错误返回
C++值对象设计
运行时接口校验
```

```text
输入名称
输入shape
输入dtype
动态维度
设备位置
内存字节数
```

今天的项目可以逐步演化为：

```text
TensorMetadata
      ↓
模型输入输出签名检查
      ↓
推理请求验证
      ↓
安全分配输入输出缓冲区
      ↓
ONNX Runtime/TensorRT适配
```

它是后续 AI 工程化项目中的基础模块，不是孤立的语法练习。
